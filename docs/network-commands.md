# 设备网络写入命令（给处暑）

设备现在最多记得 **3 个 Wi-Fi**：一个当前用的，另外两个是备用。这样设备离开固定
Wi-Fi 后不会失联——到现场自动挑能连的那个。

命令走两条通道，同一个命令层，一条一个 JSON（带自增 `id`，回执带同一个 `id`）：

- **USB 串口**：COM3，115200，一行一个 JSON
- **控制 TCP**：`154.64.231.1:18080`（设备主动连过来）

## 1. `add_net` — 只存不切（最常用）

```json
{"id": 7, "cmd": "add_net", "ssid": "vivo S16 Pro", "password": "00000000"}
```

回执：

```json
{"id": 7, "ok": true, "cmd": "add_net", "ssid": "vivo S16 Pro"}
```

错误：

| 情况 | 回执 |
|---|---|
| 没给 ssid | `{"ok": false, "err": "ssid_required"}` |
| 已满 3 个 | `{"ok": false, "err": "network_list_full"}` |

行为：

- **只写 NVS，不碰当前连接**——所以可以在固定 Wi-Fi 还通的时候先把手机热点存进去
- 同 SSID 再发一次 = 更新密码（不会新增一项）
- 写进列表末尾，不改变当前选中项

## 2. `set_net` — 存下并立即切换

```json
{"id": 8, "cmd": "set_net", "ssid": "新网络", "password": "密码"}
```

- 新网络自动加入列表并选中，**断开当前 TCP 重连**
- 可选带 `host` / `port` 同时改服务器地址（只换 Wi-Fi 时省略）
- 回执先于断链发出，所以发起方一定能收到"成没成"

## 3. `get_net` — 查看当前配置和列表

```json
{"id": 9, "cmd": "get_net"}
```

回执：

```json
{"id": 9, "ok": true, "cmd": "net",
 "ssid": "153-702", "host": "154.64.231.1", "port": 18080,
 "password_set": true, "active": 0,
 "networks": [
   {"ssid": "153-702", "password_set": true},
   {"ssid": "vivo S16 Pro", "password_set": true},
   {"ssid": "lab-guest", "password_set": true}
 ]}
```

- `active` 是当前选中项的下标（从哪里开始尝试）
- **密码永远不会出现在任何回执里**，只有 `password_set` 布尔值

## 自动切换逻辑

- 开机先连 `active` 那一项
- 60 秒拿不到 IP → 顺延到下一项，最多把 3 个都试一遍
- 连上就不再切换（不做主动轮询，避免把关联过程切碎）

## 典型流程：离场前预存手机热点

1. 固定 Wi-Fi 还通的时候，通过控制通道发：

   ```json
   {"id": 7, "cmd": "add_net", "ssid": "vivo S16 Pro", "password": "00000000"}
   ```

2. 确认：

   ```json
   {"id": 8, "cmd": "get_net"}
   → networks 里应该有 2 项，当前 ssid 还是原来的固定 Wi-Fi
   ```

3. 设备带走。到没有固定 Wi-Fi 的地方，它自己试下一个，连上手机热点。

## 限制与注意

- 最多 **3 个**网络。满了返回 `network_list_full`，**目前没有删除命令**（要换只能覆盖同 SSID，或整片擦 NVS 重新配网）
- SSID ≤ 32 字节，密码 ≤ 64 字节
- **密码是明文经服务器→设备**的（和 `set_net` 一样）。这条通道的加密在链路层（TLS/私有协议），但服务端日志、回执、聊天记录里都不要出现密码
- 手机配网页走的是同一套 NVS，两条路径（网页配网 / 命令写入）结果一致
