# `server/dsh` — dsh 连接器

## 现状

| 后端 | 状态 |
|---|---|
| `mock.py` | ✅ 确定性回复，供 mock 全链贯通 |
| `http.py` | ⚠️ **未对真实 dsh 验证**，需要先调查 dsh 实际暴露的入口 |

任务书 §U2 的要求是「通过现有、受支持的 dsh 调用方式提交识别文本并接收回复；
先调查实际 API/CLI/消息总线及权限边界，不猜测不存在的接口」。

所以这里刻意**不发明**协议：`http.py` 只是一个带注释的骨架 —— 给它一个 URL 和
token，它按 SSE/JSONL 读回复；没有 URL 时直接抛错而不是假装能用。等调查清楚
dsh 的真实入口（Feishu 桥 / ACP / CLI），再替换实现，`base.Brain` 接口不变。

## 边界（不要在这层做的事）

- 不实现权限提升：语音文本**不**因为「是语音」而获得更高操作权限，副作用操作走
  dsh 既有确认流程。
- 不把长任务取消绑到播放打断上：用户打断播报 ≠ 取消后台任务。
- 不在日志里记录完整转写文本之外的隐私内容。
