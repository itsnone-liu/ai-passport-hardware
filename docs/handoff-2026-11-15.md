# 语音链路交接（2026-11-15）

写给接手的人/agent（处暑）：这一份是"现在能跑什么、什么还没验、坑在哪"的说明。
细节数字见 `docs/voice-stage-report.md`（§1–§8 按时间累积）。

## 一句话现状

设备对着人说话 → ADPCM/UDP 上行 → 百炼 ASR → DeepSeek 回答 → 百炼 TTS →
ADPCM/UDP 下行 → 设备出声。真人三句全部识别正确，最后一次回放
`starved=0`、`underruns=0`、`overflows=0`。

## 未完成 / 已知问题

1. **误按键静默失败（建议优先修）**：服务端对**任何**按键都发 `capture.start`；
   设备端 `terminal_capture_start()` 不校验按键预热（`s_armed`），于是按到上/下键时
   设备回 `ok` 但什么都不做，`turns` 不增、无 `capture.ended`，两边都不报错。
   修法：服务端只在 OK 键（`BSP_BTN_OK`）发 start；设备端对未 arm 的 start 明确拒绝。
2. **连续对话未测**：真人只说过单句，多轮记忆、打断（barge-in）都没跑过。
3. **上行无 FEC**：实测 `lost=0`，还没被网络逼出来。
4. **弱网未测**：今天 `udp_gap=1` 丢块是 FEC 补的，但没有系统压测（`drop_every` 台架可做）。
5. `play_mismatch=4`：收轮时尾部帧未逐块对账。
6. 重放保护只到 turn 粒度，窗口外没有全局计数器。
7. **`get_net` 打爆 dsh_usb 栈（真 bug）**：该命令栈上有 `body[768]`，
   `terminal_net_describe()` 再加 `ssid[198]+host[390]`，超过任务 4096 B 栈，
   设备 `Stack protection fault` 重启。**日常按键对话不走这条路径**，
   只有主机侧发 `get_net` 才触发。修法：`proto_task` 栈提到 8192，
   或把 body 改 static（若 handle_line 被两个任务共用则需加锁）。
8. **换网坑**：SSID 大小写必须完全一致（实际 `vivo S16 Pro`，配成 `vivo s16`
   就是 `reason=201`，日志看不出是名字写错）。热点关闭时设备会 84 秒一轮
   panic 重启（`uptime`/`prev_uptime` 都停在 84/85），热点一开即恢复。

## 接 dsh（处暑）的已知事实

- **dsh 不在这台 VPS 上**（`which dsh` 为空）。它在用户的 Ubuntu 上，通过飞书桥常驻。
- 现有两条实现都不可直接用：
  - `server/dsh/cli.py` = one-shot `dsh --profile headless "<task>"`，**5.1 s/轮**
    （其中约 2.5 s 是 node 冷启动），只能做通知，不能做对话。
  - `server/dsh/http.py` = 需要 `dsh_url`，**从未验证过**。
- `cli.py` 自己的注释指出正确方向：**常驻会话（Feishu bridge 或 ACP session）**。
- `Brain` 协议：`async def astream(text, session="passport") -> AsyncIterator[str]`，
  逐块 yield 文本；`service.py` 的 `_speak()` 负责把文本喂给 TTS。
- 接之前要先定三件事：
  1. **传输**：飞书桥怎么收消息（有没有 HTTP ingress / 报文格式）
  2. **会话隔离**：设备会话必须独立（如 `passport:psp-f53038`），否则会污染用户的飞书对话
  3. **输出契约**：`SPEAK:`（2–3 句口语，进 TTS）/ `SHOW:`（长文，进屏幕或飞书）。
     长结论不能念，只能显示；这是语音与文本的体裁差异，不是压缩问题。
- 安全边界：语音不可信（谁在设备旁都能说），dsh 有 shell 权限 → 语音触发的请求**只读**，
  写操作要二次确认。

## 常用操作

```sh
# 设备状态（Windows 侧串口，DTR/RTS 必须 False，否则设备复位）
python state_raw.py            # 全字段
python state2.py               # 过滤视图

# 让设备直接说一句话（不需要按键，走 TTS → 下行）
python3 -c '...op=speak, text=...'   # admin 18090 的 speak op

# 台架压测下行
python3 admin_push2.py <frames> <turn> <shuffle> [drop_every]
python3 replay_udp.py          # 重放旧 turn（验证防重放）
```

## 坑

- **控制台是 GBK**：中文日志在 Windows 终端显示成乱码，要判断内容就写到 UTF-8
  文件再读，或 `sftp` 下来读。
- 服务端重启后，**设备最多要等 3 分钟**才重连（control 每 3 分钟轮换一次）；
  这期间按键会失败，别误判成设备坏了。
- 串口 `DTR=False`、`RTS=False`，否则一读串口设备就复位。
- 按键语义：**中间 OK 键按住说、松手停**；上下键是音量/亮度。旧固件只认短按，
  人手按住必然被判成长按去调亮度——这是之前真人测试一直失败的真因，已修。
- 判断"通道可用"必须指名指标（`underruns`/`starved`/`recovered`/`gap`），
  不接受"看起来通了"。
